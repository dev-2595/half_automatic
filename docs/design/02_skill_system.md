# 지식 (Knowledge) — 기획 02: 스테이지, 스킬, 별 시스템

> 상태: 초안 (v0.5) · 출처: 기획자 설정
> §1은 확정, §2는 확정 내용을 맞춰 본 **제안(확인 필요)**, §3은 결정이 필요한 사항이다.

## 1. 확정 사항

| # | 내용 |
|---|---|
| S1 | 모든 학습은 **가장 쉬운 것부터** 시작한다. (모든 영역이 1단계에서 시작) |
| S2 | **스킬은 스테이지 하나를 클리어하면 얻는다.** |
| S3 | **스테이지는 한 개념**(예: 곱셈)을 **난이도 단계별로 나눈 학습 단위**다. |
| S4 | 스테이지를 클리어하면 그 단계에 맞는 스킬이 주어진다. (예: 구구단을 클리어하면 **기본 스킬**) |
| S5 | 스킬의 별은 **최대 3개**이며, **황금색 8각별**이다. |
| S6 | 별 3개를 모으면 그 스킬의 **정점**을 쓸 수 있다. 정점은 **매우 강력하고 이펙트가 매우 화려하다.** |
| S7 | **후반으로 갈수록 난이도가 어려워진다.** 그만큼 **스킬 연출은 더 화려해지고, 경험치 등 보상도 더 많이 준다.** |
| S8 | 보상이 커지는 만큼 **레벨업에 필요한 경험치도 갈수록 많아진다.** |
| S9 | 한 영역 안에는 **개념이 여러 개** 있고, **개념마다 스킬이 하나**씩이다. (기획자 확인) |
| S10 | 곱셈 스킬이 구체적으로 어떤 능력인지는 **아직 정리하지 않았고, 나중에 정한다.** (보류) |

### 개념 하나의 난이도 단계 (예: 곱셈, 확정)

| 단계 | 곱셈의 예 |
|---|---|
| 기본 | 구구단 |
| 보통 | 십의 단위 곱셈 |
| 약간 심화 | 응용 |
| 심화 | 어려운 말, 다른 개념과의 조합 |

## 2. 제안: 별과 스테이지의 연결 (확인 필요)

단계가 **4개**(기본·보통·약간 심화·심화)이고 스킬 형태가 **기본 스킬 + 별 3개**이므로, 개수가 딱 맞는다.

```
개념(예: 곱셈) = 스킬 하나
 ├─ 기본 스테이지 클리어      → 스킬 습득 (기본 스킬)
 ├─ 보통 스테이지 클리어      → ★
 ├─ 약간 심화 스테이지 클리어 → ★★
 └─ 심화 스테이지 클리어      → ★★★ ⇒ 정점 해금
```

> ⚠ 이전 설정(별은 "초급·중급·상급" 각각의 심화를 마치면 오른다)과 표현이 다르다.
> 위 제안은 새로 주신 4단계 예시를 기준으로 맞춘 것이므로, 맞는지 확인이 필요하다.

### 2.0 새 맵 구조와의 관계 (확인 필요)

[기획 01 §1.1](01_learning_structure.md)에서 영역 안이 **기초 · 응용 · 심화 맵**으로 나뉘는 것이 확정되었다.
위 제안(개념 하나의 4개 스테이지 = 습득 + 별 3개)은 갈래·학교급 구분(기획 01 D6, D9)과 별개로 세운 것이므로, **어느 쪽인지 정해질 때까지 이 문서의 스킬 습득·별 규칙은 잠정이다.**
비교는 [기획 01 §3 Q1](01_learning_structure.md) 참고.

### 2.1 지켜야 할 불변 조건 (데이터 무결성)

저장된 진행 데이터가 아래를 어기면 **로드 시점에 거부**한다. (신 데이터를 `FDeityTableValidator`가 검사하는 방식과 같다.)

1. 별 개수는 0 이상 3 이하다.
2. 습득하지 않은 스킬은 별이 0개다.
3. 별은 **순서대로** 올라간다. (n번째 별은 n-1번째 별이 있어야 한다)
4. 별은 해당 단계의 **스테이지를 클리어했을 때만** 오른다.
5. 정점은 별이 정확히 3개일 때만 쓸 수 있다.
6. 클리어한 스테이지 기록은 지워지지 않는다. (별 감소 규칙이 별도로 정해지기 전까지)

### 2.2 별 외형 (확정: 모양과 색)

- **황금색 8각별.** 스킬 슬롯 옆에 최대 3개를 나란히 표시한다.
- 모양 참고: 기획자가 제시한 3D 8각별 이미지 (뾰족한 8개의 꼭짓점이 중심에서 퍼지고, 각 꼭짓점이 면으로 나뉘어 명암이 생기는 입체 별). 원본은 은회색이며 게임에서는 **금색**으로 만든다.
- 별이 아직 없는 칸은 **빈 윤곽 또는 어두운 별**로 보여 준다 (제안).
- ⚠ 참고 이미지는 출처·라이선스를 알 수 없어 저장소에 넣지 않았다. 게임 안의 별은 **직접 제작한 에셋**을 쓴다.

## 3. 성장과 보상 (S7, S8)

### 3.1 확정 내용
- 난이도가 오를수록 스테이지의 **보상(경험치 등)** 이 커진다.
- 스킬의 **연출**은 갈수록 더 화려해진다. (별 3개의 정점이 가장 화려하다. S6)
- 레벨업에 필요한 **경험치도 갈수록 커진다.**

### 3.2 설계 메모 (제안)

"성장이 빠르게 느껴지는가"는 **보상이 커지는 속도**와 **레벨업 요구량이 커지는 속도**의 비율로 정해진다.

| 비교 | 체감 |
|---|---|
| 보상 증가가 요구량 증가보다 **빠르다** | 후반일수록 레벨이 **더 빨리** 오른다 (초반 "점점 빠르게 성장"의 느낌) |
| 두 속도가 **비슷하다** | 레벨업 속도가 **일정**하다 |
| 보상 증가가 요구량 증가보다 **느리다** | 후반일수록 레벨업이 **느려진다** |

따라서 **수치를 코드에 박지 않고 표(데이터)로 관리**하는 것을 권장한다. 한 곳을 고치면 곡선 전체를 다시 조율할 수 있다.

데이터로 관리할 때 로드 시점에 거부할 조건 (제안):
1. 레벨업 필요 경험치는 **0보다 크고, 레벨이 오를수록 증가**한다.
2. 스테이지 보상은 **0 이상**이다.
3. 같은 개념 안에서 더 어려운 단계의 보상이 더 쉬운 단계보다 **작지 않다.**

## 4. 결정이 필요한 사항

### Q1. §2의 연결이 맞는가? (이전 질문, 새 맵 구조 때문에 다시 정리 필요 → [기획 01 §3 Q1](01_learning_structure.md))
- 맞다면: 개념 하나 = 스킬 하나, 4개 스테이지가 스킬 습득 + 별 3개에 대응.
- 다르다면: 별과 스테이지가 어떻게 연결되는지 알려 주세요.

### Q2. 레벨은 하나인가, 영역마다 따로인가?
- 플레이어 **전체 레벨 하나**를 모든 영역의 경험치로 올리는가
- 아니면 **영역(교과)마다 레벨**이 따로 있는가

### Q3. 경험치 말고 어떤 보상이 있는가?
"경험치나 보상"에서 경험치 외의 보상이 무엇인지 (예: 재화, 의상·장신구, 스킬 재료)

### Q4. 레벨의 끝
- 최대 레벨이 있는가, 그리고 난이도의 끝(초6 / 중3 / 고3)과 어떻게 연결되는가 → [기획 01 §3](01_learning_structure.md)

- "점점 빠르게 성장"의 뜻 → S7, S8로 확정
