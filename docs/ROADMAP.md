# 로드맵 (초안)

> 상태: 초안. 기획자(양선우)의 설명을 정리한 것이며, ⚠️ 표시는 확정이 필요한 항목.

## 1. 컨셉

- **장르**: 방치형(자동 수집) + 화려한 연출. 톤은 **병맛 코미디**.
- **세계관**: *World Of God*의 **같은 세계 외전**. 설정은 공유하되 진행은 독립.
- **주인공**: 톱 시크릿 등급의 **공간의 신**. 너무 심심해서, 그리고 "너무 강해서 처음부터 해 보고 싶다"는 이유로 환생.
  겉모습은 변하지 않는다(→ 약한 몸이 아니라 *강한 채로 하급부터 시작*하는 개그 구도).
- **게임의 목적**: 갈수록 **화려한 무기와 임팩트**를 보여 주는 것.
- **화면**: 우선 **2D**(측면 뷰, 귀여운 캐릭터 + 화려한 스킬 이펙트). 레퍼런스는 쿠키런 크럼블 느낌 ⚠️(어떤 점을 닮게 할지는 확정 필요).
- **고유 기능 "차원 바꿔버리기"**: 2.5D/3D 전환(공간의 신의 힘). **나중에 추가**한다(후순위, Phase 5).
- 기존 '반자동 공장'(고장/수리) 콘셉트는 **등급 성장 구조로 대체**한다.

## 1-1. 아트 · 연출 · 스토리 방향

핵심은 **대비**다: *임팩트는 압도적으로 화려하게, 캐릭터는 하찮고 웃기고 귀엽게.*

- **캐릭터**: 2.5등신, 동글동글하고 표정이 풍부한 귀여운 디자인. 신, 보스, 몬스터도 위엄 대신 어딘가 하찮게(진지한 설정을 귀여운 외형이 배신하는 개그).
- **임팩트**: 이펙트, 카메라 셰이크, 슬로모션, 화면 가득한 필살기는 최대한 화려하게. 무기가 좋아질수록 연출 규모가 커진다.
- **웃음의 구조**: 거창한 연출과 하찮은 캐릭터의 낙차, 최강인데 하급부터 시작하는 설정, 등급 체계 자체에 대한 자기 비하 개그.
- **스토리 톤**: 처음부터 끝까지 코미디. 시리어스한 World Of God 설정(절대신, 카오스, 다크미러)도 외전에서는 병맛으로 비튼다.
- **대사 시스템**은 개그 타이밍(말풍선 속도, 리액션 표정, 효과음)을 조절할 수 있게 데이터로 분리한다.
- ⚠️ 웃음 포인트가 되는 대사/이벤트 작성은 기획자의 감각이 중요하다. 초안은 제가 쓰되 최종 톤은 기획자가 다듬는다.

## 1-2. 주인공(공간의 신) 디자인

레퍼런스: `docs/art/protagonist_reference.png`

- **형태**: 굵고 균일한 검은 외곽선, 흰 몸, 큰 동그란 머리와 작은 몸통(약 2.5등신 이하의 아기 같은 비율).
- **얼굴**: 점 두 개의 눈과 물결 모양 입(고양이 입/콧수염처럼 보이는 미소). 표정이 단순해서 입과 눈 위치/모양 변화만으로 리액션을 만든다.
- **몸**: 짧고 뭉툭한 팔(손가락 없음), 하나로 이어진 둥근 하체에 다리 사이 틈만 있는 형태.
- **개그 포인트**: 이렇게 하찮게 생긴 몸으로 우주급 필살기를 쓴다. 무기가 화려해질수록 흰 몸과의 낙차가 커진다.

**제작 시사점**
- 파츠가 적다(머리, 몸통, 팔×2, 하체/다리×2). 2D 본 리깅이 단순하고 애니메이션 제작 비용이 낮다.
- 외곽선 두께는 해상도가 바뀌어도 일정하게 유지되어야 하므로 스프라이트 해상도와 스케일링 방식을 일찍 정한다 ⚠️.
- **장비는 없고 무기만 있다.** 방어구, 모자, 망토 같은 외형 장비는 만들지 않는다. 몸(외형)은 끝까지 그대로이고 손에 든 무기만 화려해지므로, 별도 의상 레이어가 필요 없고 핵심 개그(하찮은 몸 + 화려한 무기)와 잘 맞는다.
- 무기는 손에 붙는 단일 파츠(손 본에 부착)로 만들어 리깅과 애니메이션 부담이 작다.
- 무기 효과: **공격력 또는 방어력을 올린다.** ⚠️ 한 무기가 둘 다 올리는지, 무기마다 하나만 올리는지(예: 공격형/방어형)는 확정 필요.
- 흰 몸과 흰/밝은 배경은 대비가 약하다. 배경은 채도와 명암 대비를 충분히 준다.

## 2. 등급 체계

하급 → 중급 → 상급 → 레전드 → 킹 → 시크릿 → 톱 시크릿 → **절대신(갓)**

- 시크릿은 "시크릿"과 "톱 시크릿"으로 세분된다. (비밀 등급 안의 두 단계)
- ⚠️ 등급별 승급 조건(레벨/재화/보스), 등급당 단계 수, 무기 등급과의 대응은 미정.

## 3. World Of God에서 가져올 수 있는 설정 (후보)

*확정된 것이 아니라 외전에서 재사용 가능한 후보 목록이다.* 사용 여부를 항목별로 확정해야 한다.

| 후보 | 요약 |
|---|---|
| 절대신 / 카오스 봉인 | 세계의 기원. 노인으로 변장한 절대신 반전 |
| 8속성 | 바람·풀·물·빛·땅·불·얼음·어둠, 지형별 드랍 확률 차등 |
| 4개 지형 | 숲과 초원 / 사막 / 해변 / 빙하, 지형별 마을 재건 |
| 직업 | 전사(HP↑) / 마법사(쿨타임↓) / 힐러(버프·디버프) |
| 스킬 등급 | 희귀 5 / 초희귀 10 / 에픽 20 / 신화 30 / 레전드 50 (속성석 요구량) |
| 다크미러 | 최종 보스, 신전 붕괴·부유물 연출 |
| 게임오버 연출 | 금색 균열로 깨지는 화면 → "일어나거라" |

⚠️ 방치형에서 직업/스킬/속성석 시스템을 어디까지 쓸지는 미정.

## 4. 단계별 계획

### Phase 0 — 기반 (완료)
- [x] Unity 6(6000.7.7f1) 프로젝트, 코어/플랫폼/UI 계층 분리
- [x] 시작 화면, 게스트 로그인, 저장 무결성(체크섬), EditMode 테스트
- [ ] Unity에서 열어 컴파일/테스트 통과 확인 (사용자 환경에서 최초 1회)

### Phase 1 — 등급 성장 코어 (방치 루프)
- 자동 수집(자원/경험치) 틱, 오프라인 보상(상한 있음)
- 등급·레벨 모델과 승급 규칙 (순수 C#, 단위 테스트)
- 무기 획득(드랍/제작)과 등급별 능력치(공격력/방어력 보너스). 장착 슬롯은 무기 1개
- 저장/불러오기 (스키마 버전 관리)
- 기존 Godot 시절의 오프라인 계산·검증 로직을 C#으로 이식(고장 요소는 제외)

### Phase 2 — 계정 로그인 (아이디 + 비밀번호)
- `IAuthProvider` 추상화를 추가하고 게스트/계정 구현을 교체 가능하게 한다.
- **권장**: 직접 서버를 만들지 않고 관리형 인증(Unity Authentication의 아이디·비밀번호 로그인 등)을 사용한다.
  - 이유: 비밀번호 해시·저장·재시도 제한을 직접 구현하면 보안 책임이 크다. 클라이언트에 비밀번호를 저장하거나 자체 검증하지 않는다.
  - ⚠️ 비밀번호 규칙·지원 범위는 도입 시점의 공식 문서로 확인한다.
- 계정 연동 후에는 진행 데이터를 서버(클라우드 세이브)로 옮길지 결정한다. 치팅 방지 수준도 ⚠️ 미정.

### Phase 3 — 2D 연출 기반
- Unity 2D, 측면 뷰. 레이어 스프라이트와 패럴랙스 배경.
- 귀엽고 하찮은 2.5등신 캐릭터. 뼈대(리깅)와 관절 연결은 Unity **2D Animation 패키지**(스프라이트 본)로 구현해 부드럽게 움직이게 한다(과장된 표정/리액션 포함).
- 임팩트 연출(파티클, 카메라 셰이크, 슬로모션, 화면 가득한 스킬), 병맛 대사 시스템.
- 로직(Core)과 화면(View)은 계속 분리해 둔다 → 나중에 뷰만 3D로 바꿀 수 있게 한다.

### Phase 4 — 콘텐츠와 스토리
- 등급별 지형/무기/보스, 갈수록 화려해지는 무기 비주얼(이펙트, 크기, 변형 애니메이션)
- 컷씬(Timeline), 엔딩 크레딧(개발자: 양선우, 사용 기술 영문 표기)
- 대형 보스와 복잡한 패턴

### Phase 5 — "차원 바꿔버리기" (후순위)
- 2D → 2.5D/3D 전환 기능. 시작 전에 아래를 먼저 결정한다.
  - ⚠️ 3D 모드에서 무엇을 하는가(자유 이동 수집? 전투? 보너스 스테이지?)
  - ⚠️ 3D 에셋 제작 방식. **주의**: 2D 스프라이트 월드는 3D로 그대로 변환되지 않는다. 3D 모드에 쓸 모델/배경을 별도로 만들어야 하므로 비용이 크다.
  - 저비용 대안: 전환 시 2D 스프라이트를 3D 공간에 세워 놓는 방식(빌보드)의 2.5D로 시작한다.

## 5. 미정 사항 (결정 필요)
1. 등급 승급 조건과 밸런스 곡선
2. (후순위) 3D 모드의 역할, 범위, 에셋 제작 방식
3. World Of God 시스템(직업/스킬/속성석) 중 재사용할 항목
4. 인증 방식 확정(관리형 vs 자체 서버)과 클라우드 세이브 여부
5. 2D 아트 레퍼런스의 구체적 방향(쿠키런 크럼블에서 닮고 싶은 점)
6. 타깃 플랫폼 (PC 우선인지, 모바일 우선인지) — 폰트/해상도/입력 방식에 영향
